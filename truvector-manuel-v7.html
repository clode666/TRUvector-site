★ Cockpit d'administration (/admin)

/admin est le poste de pilotage complet (protégé par code) : il édite tout le contenu et exporte un config.json.

workflow
1. /admin  (code par défaut : truvector-admin)
2. Importer config.json  ← _v5-build/src/config.json
3. Éditer (galerie, articles, concours, dons… + upload images/audio)
4. Exporter config.json  → remplace _v5-build/src/config.json
5. node _v5-build/build.mjs open   (public)  |  node _v5-build/build.mjs (coffres)
6. committer / déployer truvector.dev/

Un nouvel article (avec contenu) est généré en articles/posts/<slug>.html. Les images/audios uploadés sont intégrés au config.json (base64).

v5 Accès : deux modes (sans Cloudflare)

Le site se génère en deux modes via _v5-build/build.mjs.

  • PUBLIC (build livré) — node _v5-build/build.mjs open : les 7 sections sont accessibles sans code ; seule /admin est protégée par code.
  • COFFRES chiffrés — node _v5-build/build.mjs : les 7 sections sont chiffrées (AES-256-GCM), déverrouillage par passphrase ou fichier-clé .trukey.

Le blog (articles) et les pages légales restent publics dans les deux cas. Code admin : truvector-admin (modifiable dans config.json → access.adminCode).

Modifier le contenu

atelier privé
1. éditer  _v5-build/src/config.json  (+ assets dans _v5-build/src/…)
2. build   node _v5-build/build.mjs open   # public (actuel)
       ou  node _v5-build/build.mjs        # coffres chiffrés
3. déployer UNIQUEMENT truvector.dev/  (jamais _v5-build/)
Aucune dépendance Cloudflare pour les droits. En mode PUBLIC, le contenu est en clair (accès sans code) ; seule l'admin exige un code.

CDN Déploiement léger — médias sur un 2ᵉ dépôt (jsDelivr)

Pour garder Cloudflare tout petit (~3 Mo), les médias lourds sont déportés sur un second dépôt GitHub servi par le CDN gratuit jsDelivr. Deux livrables :

  • truvector-site (~3 Mo) → Cloudflare Pages : HTML, CSS, JS, config.json, mini-images d'interface. Aucun MP3, aucune image de galerie, plus de vault.json.
  • truvector-assets (~33 Mo) → nouveau dépôt GitHub public clode666/truvector-assets : musique/ (36 MP3) + galerie/ (.webp + .png) + ebooks/ (.trubook, covers/*.svg, manifest.json).

Le seul réglage est dans assets/js/assets.js :

window.TRU_ASSET_BASE = "https://cdn.jsdelivr.net/gh/clode666/truvector-assets@main";

Le lecteur audio, le mini-lecteur global, la galerie et les liens e-books construisent leurs URLs à partir de cette base. Depuis la v6, le mini-lecteur connaît aussi l'adresse jsDelivr par défaut : il fonctionne même si assets.js manque ou est périmé en cache. Chaîne vide ("") = médias servis en local (mode monolithique) — le site marche dans les deux cas.

Mise en place (une fois)

  1. Crée un dépôt GitHub public truvector-assets, pousse-y le contenu de truvector-assets/.
  2. Renseigne TRU_ASSET_BASE dans assets/js/assets.js (ton user + branche, sans slash final).
  3. Déploie truvector-site/ sur Cloudflare Pages (Git ou wrangler pages deploy).

Mettre à jour un média

Remplace le fichier dans truvector-assets + git push. jsDelivr met @main en cache ~24 h–7 j ; pour forcer : purge https://purge.jsdelivr.net/gh/clode666/truvector-assets@main/<chemin>, ou crée un tag (v1…) et pointe TRU_ASSET_BASE sur @v1.

Alternative « pro » (facultatif). Stocke les médias sur Cloudflare R2 (10 Go gratuits, egress gratuit) exposé sur media.truvector.dev, et mets cette URL dans TRU_ASSET_BASE. Même mécanisme, sur ton propre domaine.
⚠️ CSP (important). Le fichier _headers définit une Content-Security-Policy stricte. C'est déjà réglé pour https://cdn.jsdelivr.net (dans img-src, media-src et connect-src — ce dernier est indispensable au lecteur d'e-books, qui télécharge les .trubook par fetch) et pour l'analytics Cloudflare (static.cloudflareinsights.com / cloudflareinsights.com). Si tu changes d'hébergement de médias, ajoute son domaine à img-src, media-src et connect-src dans _headers.
Pourquoi c'était lourd : la galerie encodait ses images en base64 dans la page (4 Mo) et chaque section gardait un vault.json chiffré inutile en mode public (~6,6 Mo). Supprimés de la structure ; la galerie pointe désormais vers des fichiers.

01 Vue d'ensemble

TRUvector.dev v7.1 est un site statique (HTML / CSS / JS, sans build ni serveur) au design romantico·geek : triskèle néon, aurores boréales, guirlandes ambrées sur fond nuit.

Il réunit une page d'accueil, neuf sections (Galerie, Logiciels, E-books, Musique, Articles, Modules, Concours, Soutenir) et un pôle légal, et se déploie sur Cloudflare Pages à partir d'un dépôt GitHub. Les médias lourds (musique, images, e-books) sont servis par un second dépôt via jsDelivr. Ses objectifs :

  • présenter la marque (le compte à rebours a atteint l'ouverture le 21/09/2026 : le site est ouvert) ;
  • publier des e-books protégés (.trubook chiffrés) en édition limitée — actuellement jusqu'au 21/10/2026 ;
  • diffuser des créations graphiques en libre téléchargement ;
  • offrir un accès simple par authentification ;
  • afficher des mentions légales conformes.
Aucune dépendance à installer. Tu peux ouvrir chaque page directement dans un navigateur, ou tout pousser sur GitHub pour un déploiement automatique.

05 Installation & déploiement

Prérequis

  • Un compte GitHub (ton pseudo : clode666).
  • Un compte Cloudflare avec le domaine truvector.dev déjà géré.
  • git installé en local (facultatif : tu peux aussi glisser les fichiers dans l'interface GitHub).

Étape 1 — Pousser sur GitHub

Place le contenu du dossier truvector.dev/ à la racine d'un nouveau dépôt.

terminal
git init
git add .
git commit -m "TRUvector.dev v7.1"
git branch -M main
git remote add origin https://github.com/clode666/truvector-dev.git
git push -u origin main

Étape 2 — Créer le projet Cloudflare Pages

  1. Dashboard Cloudflare → Workers & Pages → Create → Pages → Connect to Git.
  2. Sélectionne le dépôt truvector-dev.
  3. Framework preset : None.
  4. Build command : (laisser vide).
  5. Build output directory : / (racine).
  6. Clique Save and Deploy.
Le site n'a AUCUN build. Si Cloudflare tente npx hugo (ou un autre build) et échoue, c'est une auto-détection erronée. Correctifs : Pages → preset None + Build command vide ; ou Workers (npx wrangler deploy) → le fichier wrangler.toml fourni (à la racine du dépôt) désactive l'auto-détection et sert le dossier tel quel. Vérifie que le contenu de truvector.dev/ est à la racine du dépôt (index.html et wrangler.toml tout en haut).

Étape 3 — Brancher le domaine

  1. Ton projet Pages → Custom domains → Set up a custom domain.
  2. Saisis truvector.dev (et éventuellement www).
  3. DNS + HTTPS se configurent automatiquement (domaine déjà chez Cloudflare).
Mises à jour automatiques. Chaque git push sur main redéploie le site tout seul.

06 Authentification

Deux façons de protéger la galerie. La première est la vraie sécurité ; la seconde est fournie prête à l'emploi mais légère.

Option A — Cloudflare Access (recommandé)

Gratuit jusqu'à 50 utilisateurs, aucune ligne de code, connexion par code e-mail à usage unique ou Google.

  1. Cloudflare → Zero Trust → Access → Applications → Add an application → Self-hosted.
  2. Domaine : truvector.dev · Chemin : /galerie.
  3. Ajoute une policy Allow → règle « Emails » (les tiens / autorisés) ou « One-time PIN ».
  4. Enregistre. La galerie demande désormais une connexion en amont du site.
Avec Access, tu peux retirer la porte JS (voir plus bas) : la protection est gérée par Cloudflare.

Option B — Porte d'accès légère (incluse)

Un verrou par code, déjà en place dans galerie/index.html. Change le code ici :

galerie/index.html
var ACCESS_CODE = "truvector2026";   // ← mets ton propre code
Limite. Le code est visible dans la source de la page : c'est un filtre « doux », pas une sécurité réelle. Pour du sérieux, utilise l'option A.

Retirer la porte JS (si tu passes sur Access)

Dans galerie/index.html, supprime le bloc <div class="gate" id="gate">…</div> ainsi que le script commenté « PORTE D'ACCÈS ».

Codes par section

Chaque section (logiciels, e-books, musique, articles, dons, concours, modules) a son propre code dans config.access.sections, modifiable depuis le panneau d'admin (bloc « Sections & codes »). Chaque accès est mémorisé indépendamment le temps de la session.

Protéger aussi l'admin

La page /admin a sa propre porte (code adminCode dans config.json). Protège /admin et /galerie avec Cloudflare Access ; les rôles (admin / éditeur / lecteur) définis dans le panneau se transposent en règles Access (liste d'e-mails exportable depuis l'admin).

07 Compte à rebours

La date d'ouverture et le statut du site sont définis dans config.json (modifiables depuis le panneau d'admin). assets/js/countdown.js les lit ; une valeur de repli identique reste inscrite dans assets/js/config.js.

config.json
"status": "auto",          // "soon" (bientôt) | "open" (ouvert) | "auto" (par date)
"launchDate": "2026-09-21T00:00:00+02:00"
  • +02:00 = heure de Paris (CEST). Garde ce décalage pour viser minuit à Paris.
  • Avant la date : l'accueil affiche le décompte et « reviens le 21/09 ».
  • À échéance : le décompte affiche « le site est ouvert » et le bouton Entrer dans la galerie apparaît automatiquement. Rien à faire le jour J.
Le même script pilote l'accueil ; il ne s'exécute que si les éléments #cd-grid / #launch-gate sont présents, donc inutile sur les autres pages.

08 Maintenance & évolutions

Ajouter une nouvelle créa

  1. Dépose deux versions dans galerie/assets/ :
    mon-oeuvre.webp (affichage) et mon-oeuvre.png (téléchargement HD).
  2. Duplique un bloc <figure class="art">…</figure> dans galerie/index.html et adapte :
galerie/index.html
<figure class="art square" data-full="assets/mon-oeuvre.webp"
        data-dl="assets/mon-oeuvre.png" data-title="Mon œuvre">
  <button class="art-view" aria-label="Agrandir « Mon œuvre »">
    <img src="assets/mon-oeuvre.webp" width="1024" height="1024"
         loading="lazy" alt="description de l'image">
  </button>
  <figcaption><span class="art-title">Mon œuvre</span>
    <a class="dl" href="assets/mon-oeuvre.png" download>↓ PNG HD</a></figcaption>
</figure>

Classes utiles : square (format carré) ou wide (bannière large, occupe 2 colonnes).

Générer les WebP (optimisation)

Pour alléger l'affichage tout en gardant le PNG HD au téléchargement :

exemple (ImageMagick)
# WebP d'affichage, largeur max 1600px
magick mon-oeuvre.png -resize 1600x> -quality 82 mon-oeuvre.webp

Modifier une page ou le style

  • Texte / structure : édite le index.html concerné.
  • Couleurs, espacements, composants : assets/css/tokens.css.

Publier une mise à jour

terminal
git add .
git commit -m "maj : nouvelle créa + textes"
git push

Cloudflare Pages redéploie automatiquement en quelques secondes.

Mesure d'audience (sans cookies)

  1. Cloudflare → Web Analytics → Add a site → truvector.dev.
  2. Colle le petit snippet fourni juste avant </body> des pages à suivre.

12 Configuration (config.json)

config.json, à la racine, est la source de vérité unique du site : statut, date d'ouverture, accès, droits, licence, couleur d'accent et galerie. Les pages le lisent au chargement.

config.json (extrait)
{
  "status": "auto",
  "launchDate": "2026-09-21T00:00:00+02:00",
  "access": {
    "method": "soft",             // "soft" | "cloudflare-access"
    "code": "truvector2026",       // porte galerie
    "adminCode": "truvector-admin",  // porte admin
    "users": [ { "email": "tristan@truvector.dev", "role": "admin" } ]
  },
  "theme": { "accent": "#34f5c5" },
  "license": "…",
  "gallery": [ { "slug": "coeur-aurore", "title": "Cœur d'aurore",
                 "format": "square", "visible": true, "download": true } ]
}

Priorité de lecture : valeurs par défaut (assets/js/config.js) < config.json (committé) < aperçu local (localStorage du panneau d'admin).

Le site marche même sans config.json. Les valeurs par défaut sont inscrites dans config.js : ouvert en local (file://), config.json prend le relais une fois en ligne.

13 Panneau d'administration

Accessible sur /admin, il édite config.json sans toucher au code : paramètres, accès, droits, galerie, licence.

Ce qu'on y règle

  • Paramètres : statut (bientôt / ouvert / auto), date d'ouverture, couleur d'accent.
  • Accès : méthode (Cloudflare Access ou porte JS), code galerie, code admin.
  • Droits : liste d'utilisateurs + rôles (admin / éditeur / lecteur).
  • Galerie : titre, format, visibilité, téléchargement et ordre de chaque créa.
  • Licence : texte affiché sous la galerie.

Le flux de travail

  1. Aperçu (local) — enregistre dans ton navigateur pour voir le rendu tout de suite.
  2. Exporter config.json — télécharge le fichier ; remplace celui du dépôt et committe pour appliquer à tout le monde.
  3. Emails (Access) — exporte la liste d'e-mails à coller dans une policy Cloudflare Access.
  4. Réinitialiser l'aperçu — efface l'aperçu local et recharge config.json.
Sécurité. La porte du panneau est un verrou léger (code visible dans la source). Pour une vraie protection, place /admin derrière Cloudflare Access. Les droits sont appliqués à la porte par Access, pas par le JavaScript.

14 E-books protégés (.trubook)

Un .trubook est un fichier JSON chiffré en AES-256-GCM. Il contient le livre (HTML, PDF, EPUB, CBZ, image ou texte) et sa politique : date d'expiration, pages max, durée, filigrane. Tout se déchiffre dans le navigateur du lecteur.

Le parcours d'un lecteur

  1. Il clique « Lire » sur ebooks/ → lecteur.html?src=<url du .trubook>&k=truvector.
  2. La visionneuse télécharge le fichier depuis jsDelivr, affiche la fenêtre de clé (passphrase pré-remplie).
  3. « Déverrouiller » → déchiffrement local ; un livre HTML est découpé une page par chapitre (<h2>).

Publier une nouvelle

  1. Ouvre ebooks/proteger.html, charge le fichier source, passphrase truvector, date d'expiration.
  2. Pousse le .trubook dans truvector-assets/ebooks/<slug>.trubook (+ couverture dans covers/).
  3. Le nom doit correspondre exactement au lien de la carte dans ebooks/index.html.
Date d'expiration = dans le fichier. Les .trubook actuels expirent le 21/10/2026. La page e-books, la carte d'accueil et manifest.json affichent cette même date. Pour prolonger, il faut re-chiffrer chaque livre avec la nouvelle date, puis mettre à jour les 4 endroits.
Disponibilité automatique. La page e-books vérifie chaque fichier sur le CDN : un .trubook absent affiche « Bientôt en ligne » au lieu d'un lecteur vide. État au 23/09/2026 : 3 fichiers publiés sur 21.

Rappel honnête : aucune visionneuse web n'empêche une capture d'écran. Filigrane, flou quand la fenêtre perd le focus et limites de lecture dissuadent et rendent une fuite traçable.

15 Filtres & recherche

assets/js/filters.js ajoute automatiquement une barre de recherche, des catégories cliquables et un tri A→Z aux listes du site. Aucune modification du HTML n'est nécessaire.

PageListeCatégorie lue dans

16 Cache & versions (?v=)

Les pages chargent les fichiers partagés avec un numéro de version (tokens.css?v=7, player.js?v=3…). Changer ce numéro force tous les navigateurs à reprendre le nouveau fichier.

FichiersCache (dans _headers)
/assets/js/*, /assets/css/*5 minutes + revalidation (ils changent souvent)
/assets/img/*, /assets/vendor/*, /galerie/assets/*1 an, immutable (ils ne changent jamais)
Leçon de la v5. Tout /assets/* était en cache immutable d'un an : un player.js corrigé sans changer son ?v= restait bloqué dans les navigateurs (mini-lecteur muet hors page Musique). Règle : fichier JS/CSS modifié → +1 sur son ?v= dans toutes les pages.
versions en vigueur (v7.1)
tokens.css?v=7   fx.css?v=3   assets.js?v=2   nav.js?v=5
player.js?v=6    fx.js?v=3    tru-reader.js?v=3   filters.js?v=4
(les modules assets/js/fx/*.js suivent automatiquement le ?v= de fx.js)
Service worker. sw.js garde une copie hors ligne des pages, en « réseau d'abord » : en ligne, le visiteur reçoit toujours la version fraîche. Si tu modifies sw.js, change sa constante V (tv-v6-1 → tv-v6-2) pour purger les anciennes copies.

Commande pratique pour tout incrémenter d'un coup (exemple pour player.js de v3 à v4) :

bash
grep -rl "player.js?v=3" --include=*.html . | xargs sed -i 's/player\.js?v=3/player.js?v=6/g'

18 Effets visuels (FX)

La roadmap visuelle est intégrée en totalité : assets/css/fx.css (après tokens.css) et assets/js/fx.js (en fin de page) sur toutes les pages. Aucune librairie externe, CSP inchangée.

Architecture : un noyau + des modules à la demande

Le noyau (fx.js) contient ce qui sert partout. Chaque page ne télécharge en plus que son module, détecté automatiquement :

Budget tenu. Pire cas (galerie + palette ouverte) : 24,9 Ko minifiés, ~10 Ko réellement transférés — sous le plafond de 25 Ko fixé par la roadmap. Au chargement d'une page : 14 à 18 Ko.

Modifier un effet (build)

  1. Édite la source lisible dans assets/js/src/ (fx.js ou fx/<module>.js).
  2. Lance bash tools/build-fx.sh (Node.js requis ; télécharge terser au premier usage) : il minifie et affiche les poids.
  3. Incrémente fx.js?v= dans les pages (les modules suivent automatiquement).
Lisibilité mesurée. Sur l'aurore à pleine intensité : texte secondaire des articles 8,9:1, texte principal 17,4:1, sous-titres de section 5,2:1 (minimum WCAG AA : 4,5:1). Assuré par le voile --voile sous le contenu et une ombre sous les titres.

Ce que fait chaque phase

  • 1 · Fondations — transitions animées entre pages (View Transitions : Chrome, Edge, Safari récents ; ailleurs, changement de page classique), titres en dégradé d'aurore, détecteur de puissance.
  • 2 · Aurore — ciel WebGL plein écran qui suit la souris et s'assombrit au scroll, 3 couches d'étoiles en parallaxe au scroll, étoiles filantes (15–30 s), triskèle qui se dessine une fois par session, guirlandes reliées en constellation autour du curseur (en-têtes de section).
  • 3 · Matière — cartes inclinables avec bordure-projecteur, boutons magnétiques et onde au clic, apparitions au scroll, halo curseur (souris uniquement).
  • 4 · Sections — Musique : anneau spectral autour du disque + barres, disque et aurore qui pulsent sur les basses, mini-égaliseur branché sur le vrai son dans le mini-lecteur. E-books : couvertures 3D, tourne de page dans la visionneuse. Logiciels : terminal + fiche détaillée par produit (fiche.html?p=…). Articles : barre de lecture, temps de lecture, « Copier », sommaire qui suit le scroll, « Tu aimeras aussi ». Modules : grille d'arcade, aperçu en direct au survol, records locaux (2048, Serpent, Photon Break, CipherLock). Galerie : l'image s'agrandit depuis sa vignette, navigation ←/→ et glisser, mosaïque qui se recompose, profondeur au gyroscope sur mobile.
  • 5 · Découverte — palette Ctrl+K (bouton ⌕ dans la barre) : sections, articles, pistes (lecture directe), e-books (via manifest.json), modules, actions. Favoris ♥ sur chaque carte, en tête de la palette, Nouveautés / Derniers ajouts, article au hasard. Filtres multi-catégories dont les exclus s'effacent en fondu pendant que les autres glissent à leur place.
  • 6 · Secrets — code Konami (↑↑↓↓←→←→BA) : « Matrix aurore » + arpège 8-bit ; couleurs de l'aurore selon l'heure ; sons d'interface optionnels ; page 404 jouable ; site installable.
Robustesse. Chaque module de fx.js est isolé : si l'un échoue sur un navigateur exotique, les autres continuent. Le site reste utilisable sans JavaScript.
