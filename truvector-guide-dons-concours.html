// 1 — les dons

Soutenir TRUvector

Objectif : proposer un soutien chaleureux, jamais mendiant. On offre un « café cosmique » pour faire vivre l'atelier — pas une quête. Dis ce que ça finance (nouvelles créas, temps de dev, hébergement) et remercie.

Quelle plateforme choisir ?

Tout marche en statique : ce sont de simples liens vers des services externes (aucun backend à héberger).

Ma reco pour toi (artiste-auteur + dev) : Ko-fi (ponctuel + petite boutique) + GitHub Sponsors (public dev) + éventuellement Liberapay (récurrent). PayPal en secours.

Bonnes pratiques

  • Un « pourquoi » en une phrase + un merci sincère.
  • Suggère des montants (2 € / 5 € / 10 €) pour lever l'hésitation.
  • Transparence sur l'usage des dons ; pas de pression.
  • Remercie publiquement les soutiens (avec leur accord).
// 2 — les concours

Animer la communauté

Des défis créatifs réguliers (trimestriels) qui collent à l'univers : « Crée ta scène romantico·geek », « Meilleur mini-outil », « Fan-art aurore ». Lots simples : mise en avant dans la galerie, goodies, une licence de tes logiciels, un accès.

Faire tourner un concours… sans backend

  1. Annoncer : titre, thème, règles, dates (début/fin), lot, comment participer.
  2. Recevoir les participations (au choix) :
    • E-mail dédié (concours@truvector.dev)
    • GitHub : Issues / Discussions (ou dépôt de Pull Request pour du code)
    • Formulaire tiers : Tally, Google Forms, Formspree, Framaforms (RGPD-friendly)
    • Réseaux sociaux avec un hashtag
  3. Départager : jury (toi) ou vote public (Framadate, StrawPoll, ou 👍 sur GitHub).
  4. Annoncer les gagnants : sur la page Concours + e-mail.
  5. Archiver les éditions passées (statut « Terminé »).

Concours (mérite)

Gagnant choisi sur la qualité/créativité. Recommandé — cadre le plus souple.

Tirage au sort (hasard)

Relève de la « loterie » : participation gratuite et sans obligation d'achat obligatoire.

// 3 — brancher sur le site

Configurer Dons & Concours

Tout se règle dans la config. En v5 (coffres), édite _v5-build/src/config.json puis relance le build ; en build de test « ouvert », c'est déjà affiché.

Dons — config.dons

config.json → dons
"dons": {
  "intro": "TRUvector est un projet indépendant…",
  "links": [
    { "label": "☕ Offrir un café", "url": "https://ko-fi.com/tonpseudo" },
    { "label": "❤ GitHub Sponsors", "url": "https://github.com/sponsors/clode666" },
    { "label": "🔁 Don régulier",   "url": "https://liberapay.com/tonpseudo" }
  ]
}

Chaque entrée devient un bouton. Laisse links vide pour afficher « bientôt disponible ».

Concours — config.concours

config.json → concours
"concours": [
  {
    "title":  "Aurora Fan-Art #1",
    "desc":   "Crée une scène romantico·geek sous les aurores…",
    "status": "En cours",        // "Bientôt" | "En cours" | "Terminé"
    "dates":  "01 → 30 nov. 2026",
    "url":    "https://forms.tally.so/…"   // règlement / participation
  }
]

Chaque entrée devient une carte (badge de statut + dates + bouton « Participer »). Liste vide → « Aucun concours en cours ».

Rappel v5. Après modif de _v5-build/src/config.json : node _v5-build/build.mjs (coffres) — ou pour tester sans code : node _v5-build/build.mjs open.
// 4 — aspects légaux (France)

Ce qu'il faut savoir

Dons

  • Les dons/tips reçus sont des revenus → à déclarer (BNC, régime artiste-auteur).
  • Don pur (sans contrepartie) ≠ vente (avec contrepartie : fichier, accès) → si contrepartie, ce sont tes CGV qui s'appliquent.
  • HelloAsso est réservé aux associations : en entreprise individuelle, utilise Ko-fi / Liberapay / Stripe / PayPal.
  • Pas de reçu fiscal ni d'avantage fiscal à promettre (réservé aux organismes habilités).
  • Si tu collectes un e-mail (remerciement, newsletter) → RGPD : finalité, base légale, mention.

Concours

  • Règlement écrit fortement recommandé, mis en ligne : organisateur, objet, participation, dates, désignation des gagnants, lots, données perso, acceptation.
  • Gratuité de participation pour un tirage au sort (loterie publicitaire) — pas d'obligation d'achat.
  • Le dépôt chez huissier n'est plus systématiquement obligatoire, mais reste conseillé pour de gros lots.
  • RGPD : ne collecte que le nécessaire (nom, e-mail), informe, et supprime après le concours.
  • Mineurs : autorisation parentale selon l'âge et le lot.
  • Lots : pour des lots modestes, obligations minimes ; au-delà, vérifier la fiscalité.
Important. Je ne suis pas juriste : ce guide donne les repères usuels. Fais relire ton règlement de concours et vérifie ta situation dons/fiscalité avec ton comptable ou l'URSSAF Artistes-Auteurs avant de lancer.
