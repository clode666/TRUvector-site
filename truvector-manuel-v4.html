01 Vue d'ensemble

TRUvector.dev v4 est un site statique (HTML / CSS / JS, sans build ni serveur) au design romantico·geek : triskèle néon, aurores boréales, guirlandes ambrées sur fond nuit.

Il tient sur trois pages plus une galerie protégée, et se déploie sur Cloudflare Pages à partir d'un dépôt GitHub. Ses objectifs :

  • présenter la marque avec un compte à rebours jusqu'à l'ouverture (21/09/2026) ;
  • diffuser des créations graphiques en libre téléchargement ;
  • offrir un accès simple par authentification ;
  • afficher des mentions légales conformes.
Aucune dépendance à installer. Tu peux ouvrir chaque page directement dans un navigateur, ou tout pousser sur GitHub pour un déploiement automatique.

02 Contenu du site

Accueil — index.html (public)

  • Héros : triskèle animé, logo néon, baseline « Where Code Meets Creativity ».
  • Compte à rebours vers le 21/09/2026, mis à jour chaque seconde.
  • Porte de lancement : le bouton « Entrer dans la galerie » reste caché jusqu'au jour J, puis apparaît automatiquement quand le décompte atteint zéro.
  • Bloc « ce qui t'attend » + carte « le créateur » (avatar + liens).

Galerie — galerie/index.html (protégée)

  • Porte d'accès (code) affichée au chargement — voir §06.
  • Grille responsive de 6 créations, chacune en .webp (affichage léger) et .png HD (téléchargement).
  • Visionneuse plein écran (clic sur une image, fermeture par ✕ ou Échap).
  • Encart licence d'utilisation.

Pôle légal & conformité

Quatre pages complètes, renseignées avec l'identité réelle de l'entreprise et reliées entre elles (et depuis le pied de page) :

  • mentions-legales/ — éditeur, directeur de publication, hébergeur, propriété intellectuelle.
  • cgv/ — conditions générales de vente / d'utilisation (vente = licence d'œuvre, pas prestation de service).
  • confidentialite/ — politique de confidentialité (RGPD).
  • cookies/ — politique de cookies (strictement nécessaires uniquement).
  • securite/ — politique de sécurité (SSI) + divulgation responsable, avec /.well-known/security.txt.

Sections thématiques (un code par page)

Accessibles depuis le hub de l'accueil (index.html#sections). Chacune possède son propre code (config.access.sections) :

  • logiciels/ — catalogue (pré-rempli, éditable via config.catalog.logiciels).
  • ebooks/ — e-books et publications.
  • musique/ — lecteur audio ; fichiers dans musique/assets/, déclarés dans config.catalog.musique. La case « lecture en fond (tout le site) » fait suivre la musique sur toutes les pages (mini-lecteur en bas à droite ; léger blanc au changement de page, un clic sur ▶ parfois nécessaire après la 1re navigation).
  • articles/ — notes et tutoriels.
  • dons/ — page de soutien (config.dons.links).
  • concours/ — jeux-concours (config.concours).
  • modules/ — modules interactifs (config.catalog.modules).

Roadmap — roadmap.html (bonus)

La feuille de route v4, autonome, aux mêmes couleurs.

05 Installation & déploiement

Prérequis

  • Un compte GitHub (ton pseudo : clode666).
  • Un compte Cloudflare avec le domaine truvector.dev déjà géré.
  • git installé en local (facultatif : tu peux aussi glisser les fichiers dans l'interface GitHub).

Étape 1 — Pousser sur GitHub

Place le contenu du dossier truvector.dev/ à la racine d'un nouveau dépôt.

terminal
git init
git add .
git commit -m "TRUvector.dev v4"
git branch -M main
git remote add origin https://github.com/clode666/truvector-dev.git
git push -u origin main

Étape 2 — Créer le projet Cloudflare Pages

  1. Dashboard Cloudflare → Workers & Pages → Create → Pages → Connect to Git.
  2. Sélectionne le dépôt truvector-dev.
  3. Framework preset : None.
  4. Build command : (laisser vide).
  5. Build output directory : / (racine).
  6. Clique Save and Deploy.
Le site n'a AUCUN build. Si Cloudflare tente npx hugo (ou un autre build) et échoue, c'est une auto-détection erronée. Correctifs : Pages → preset None + Build command vide ; ou Workers (npx wrangler deploy) → le fichier wrangler.toml fourni (à la racine du dépôt) désactive l'auto-détection et sert le dossier tel quel. Vérifie que le contenu de truvector.dev/ est à la racine du dépôt (index.html et wrangler.toml tout en haut).

Étape 3 — Brancher le domaine

  1. Ton projet Pages → Custom domains → Set up a custom domain.
  2. Saisis truvector.dev (et éventuellement www).
  3. DNS + HTTPS se configurent automatiquement (domaine déjà chez Cloudflare).
Mises à jour automatiques. Chaque git push sur main redéploie le site tout seul.

06 Authentification

Deux façons de protéger la galerie. La première est la vraie sécurité ; la seconde est fournie prête à l'emploi mais légère.

Option A — Cloudflare Access (recommandé)

Gratuit jusqu'à 50 utilisateurs, aucune ligne de code, connexion par code e-mail à usage unique ou Google.

  1. Cloudflare → Zero Trust → Access → Applications → Add an application → Self-hosted.
  2. Domaine : truvector.dev · Chemin : /galerie.
  3. Ajoute une policy Allow → règle « Emails » (les tiens / autorisés) ou « One-time PIN ».
  4. Enregistre. La galerie demande désormais une connexion en amont du site.
Avec Access, tu peux retirer la porte JS (voir plus bas) : la protection est gérée par Cloudflare.

Option B — Porte d'accès légère (incluse)

Un verrou par code, déjà en place dans galerie/index.html. Change le code ici :

galerie/index.html
var ACCESS_CODE = "truvector2026";   // ← mets ton propre code
Limite. Le code est visible dans la source de la page : c'est un filtre « doux », pas une sécurité réelle. Pour du sérieux, utilise l'option A.

Retirer la porte JS (si tu passes sur Access)

Dans galerie/index.html, supprime le bloc <div class="gate" id="gate">…</div> ainsi que le script commenté « PORTE D'ACCÈS ».

Codes par section

Chaque section (logiciels, e-books, musique, articles, dons, concours, modules) a son propre code dans config.access.sections, modifiable depuis le panneau d'admin (bloc « Sections & codes »). Chaque accès est mémorisé indépendamment le temps de la session.

Protéger aussi l'admin

La page /admin a sa propre porte (code adminCode dans config.json). Protège /admin et /galerie avec Cloudflare Access ; les rôles (admin / éditeur / lecteur) définis dans le panneau se transposent en règles Access (liste d'e-mails exportable depuis l'admin).

07 Compte à rebours

La date d'ouverture et le statut du site sont définis dans config.json (modifiables depuis le panneau d'admin). assets/js/countdown.js les lit ; une valeur de repli identique reste inscrite dans assets/js/config.js.

config.json
"status": "auto",          // "soon" (bientôt) | "open" (ouvert) | "auto" (par date)
"launchDate": "2026-09-21T00:00:00+02:00"
  • +02:00 = heure de Paris (CEST). Garde ce décalage pour viser minuit à Paris.
  • Avant la date : l'accueil affiche le décompte et « reviens le 21/09 ».
  • À échéance : le décompte affiche « le site est ouvert » et le bouton Entrer dans la galerie apparaît automatiquement. Rien à faire le jour J.
Le même script pilote l'accueil ; il ne s'exécute que si les éléments #cd-grid / #launch-gate sont présents, donc inutile sur les autres pages.

08 Maintenance & évolutions

Ajouter une nouvelle créa

  1. Dépose deux versions dans galerie/assets/ :
    mon-oeuvre.webp (affichage) et mon-oeuvre.png (téléchargement HD).
  2. Duplique un bloc <figure class="art">…</figure> dans galerie/index.html et adapte :
galerie/index.html
<figure class="art square" data-full="assets/mon-oeuvre.webp"
        data-dl="assets/mon-oeuvre.png" data-title="Mon œuvre">
  <button class="art-view" aria-label="Agrandir « Mon œuvre »">
    <img src="assets/mon-oeuvre.webp" width="1024" height="1024"
         loading="lazy" alt="description de l'image">
  </button>
  <figcaption><span class="art-title">Mon œuvre</span>
    <a class="dl" href="assets/mon-oeuvre.png" download>↓ PNG HD</a></figcaption>
</figure>

Classes utiles : square (format carré) ou wide (bannière large, occupe 2 colonnes).

Générer les WebP (optimisation)

Pour alléger l'affichage tout en gardant le PNG HD au téléchargement :

exemple (ImageMagick)
# WebP d'affichage, largeur max 1600px
magick mon-oeuvre.png -resize 1600x> -quality 82 mon-oeuvre.webp

Modifier une page ou le style

  • Texte / structure : édite le index.html concerné.
  • Couleurs, espacements, composants : assets/css/tokens.css.

Publier une mise à jour

terminal
git add .
git commit -m "maj : nouvelle créa + textes"
git push

Cloudflare Pages redéploie automatiquement en quelques secondes.

Mesure d'audience (sans cookies)

  1. Cloudflare → Web Analytics → Add a site → truvector.dev.
  2. Colle le petit snippet fourni juste avant </body> des pages à suivre.

12 Configuration (config.json)

config.json, à la racine, est la source de vérité unique du site : statut, date d'ouverture, accès, droits, licence, couleur d'accent et galerie. Les pages le lisent au chargement.

config.json (extrait)
{
  "status": "auto",
  "launchDate": "2026-09-21T00:00:00+02:00",
  "access": {
    "method": "soft",             // "soft" | "cloudflare-access"
    "code": "truvector2026",       // porte galerie
    "adminCode": "truvector-admin",  // porte admin
    "users": [ { "email": "tristan@truvector.dev", "role": "admin" } ]
  },
  "theme": { "accent": "#34f5c5" },
  "license": "…",
  "gallery": [ { "slug": "coeur-aurore", "title": "Cœur d'aurore",
                 "format": "square", "visible": true, "download": true } ]
}

Priorité de lecture : valeurs par défaut (assets/js/config.js) < config.json (committé) < aperçu local (localStorage du panneau d'admin).

Le site marche même sans config.json. Les valeurs par défaut sont inscrites dans config.js : ouvert en local (file://), config.json prend le relais une fois en ligne.

13 Panneau d'administration

Accessible sur /admin, il édite config.json sans toucher au code : paramètres, accès, droits, galerie, licence.

Ce qu'on y règle

  • Paramètres : statut (bientôt / ouvert / auto), date d'ouverture, couleur d'accent.
  • Accès : méthode (Cloudflare Access ou porte JS), code galerie, code admin.
  • Droits : liste d'utilisateurs + rôles (admin / éditeur / lecteur).
  • Galerie : titre, format, visibilité, téléchargement et ordre de chaque créa.
  • Licence : texte affiché sous la galerie.

Le flux de travail

  1. Aperçu (local) — enregistre dans ton navigateur pour voir le rendu tout de suite.
  2. Exporter config.json — télécharge le fichier ; remplace celui du dépôt et committe pour appliquer à tout le monde.
  3. Emails (Access) — exporte la liste d'e-mails à coller dans une policy Cloudflare Access.
  4. Réinitialiser l'aperçu — efface l'aperçu local et recharge config.json.
Sécurité. La porte du panneau est un verrou léger (code visible dans la source). Pour une vraie protection, place /admin derrière Cloudflare Access. Les droits sont appliqués à la porte par Access, pas par le JavaScript.
